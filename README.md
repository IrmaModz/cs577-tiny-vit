## Project overview

In this project, we implement a small version of the Vision Transformer (ViT)
from *An Image Is Worth 16x16 Words* (Dosovitskiy et al., ICLR 2021).

We train a model with about 1.2 million parameters from scratch on CIFAR-10.
The project includes:

- 49 correctness tests.
- A patch-size comparison (4×4 and 8×8 patches).
- Three training runs with different seeds for each patch size.
- An efficiency comparison based on speed, memory, parameter count, and FLOPs.

The full report is available in `docs/report/`.

## Quick start

The project was tested on Google Colab with an NVIDIA L4 GPU
using Python 3.13.16, PyTorch 2.14.1, and CUDA 13.0.

```bash
git clone https://github.com/IrmaModz/cs577-tiny-vit.git
cd cs577-tiny-vit
pip install -r requirements.txt
```

Run the following commands:

```bash
# Run all 49 tests on CPU
pytest -q

# Run one training epoch on fake data
python main.py smoke

# Check if the model can overfit a small batch
python main.py sanity

# Show tensor shapes after each model component
python main.py trace --experiment baseline_p4

# Compare patch sizes using three seeds each
python main.py ablate

# Measure speed, memory, parameters, and FLOPs
python main.py profile
```

The full ablation takes about 30 minutes on an NVIDIA L4 GPU.

The notebook `notebooks/run_project.ipynb` runs the same commands on Colab.

To enable GPU, go to Runtime → Change runtime type → GPU.

For computers without a GPU, see
[Installation on CPU](#installation-on-cpu-mac-or-computer-without-gpu).

## Expected results

| Experiment | Patch size | Tokens | Test accuracy (mean ± std, 3 seeds) | Parameters |
|---|---|---|---|---|
| `baseline_p4` | 4×4 | 65 | 78.58 ± 0.25% | 1,205,898 |
| `ablation_p8` | 8×8 | 17 | 69.67 ± 0.06% | 1,218,186 |

Patch size 4 gives higher test accuracy for all three seeds.
The differences are 8.73, 8.82, and 9.20 percentage points.

Since strict deterministic mode is disabled, repeated GPU runs may give
different results. Training and profiling times may also differ depending
on the hardware.

## Reproducibility

- **Seeds:** We use training seeds 0, 1, and 2. These seeds control
  weight initialization, data shuffling, augmentation, and DataLoader workers.

- **Data split:** We split the 50,000 CIFAR-10 training images into
  45,000 training and 5,000 validation images. The validation set contains
  500 images from each class. We use `split_seed = 0` for all experiments.

- **Test set:** We use the 10,000 test images only after the last
  training epoch of each run.

- **Configuration:** Model and training settings are stored in
  `configs/config.py`. The two main experiments in
  `configs/experiments.json` differ only in patch size.

- **Environment:** Each training result stores the configuration, seed,
  software versions, and hardware information.

- **Dependencies:** The versions used on Colab are listed in
  `requirements.txt`.

## Tests

Run all tests using:

```bash
pytest -q
```

The project includes 49 tests that run on CPU without downloading CIFAR-10.

The tests check:

- Patch embedding against PyTorch's `Conv2d`.
- Custom attention against `nn.MultiheadAttention`.
- Patch order, tensor shapes, and parameter counts.
- Encoder behavior with different token counts and token order.
- Gradient correctness using float64 `gradcheck`.
- Gradient flow from the classification loss to patch tokens.
- Training on a small fixed batch.
- Controlled failures using a detached gradient path and zero learning rate.

## Data preprocessing

We calculated the mean and standard deviation using all pixels from
the 50,000 original CIFAR-10 training images.
Pixel values were scaled to [0, 1].

- Mean (RGB): (0.4914, 0.4822, 0.4465)
- Standard deviation (RGB): (0.2470, 0.2435, 0.2616)

We verified these values using NumPy.

For training images, we use random cropping with padding 4,
random horizontal flipping, and normalization.

Validation and test images are converted to tensors and normalized
without augmentation.

Dataset source:
[Official CIFAR-10 dataset](https://www.cs.toronto.edu/~kriz/cifar.html).

The dataset is downloaded automatically by torchvision into `data/`.
It is not included in the repository.

## Results

All experiment results are generated by our code and saved in `results/`.

We include these small output files in the repository,
but not the datasets or model checkpoints.

### `results/ablation/`

Generated by:

```bash
python main.py ablate
```

- `<experiment>_seed<seed>.json`: Stores the configuration, environment
  information, training and validation metrics for each epoch,
  final test results, parameter count, and training time.

- `summary.csv`: Stores the mean and standard deviation of test accuracy,
  mean training time, and parameter count for each experiment.

### `results/profiling/`

Generated by:

```bash
python main.py profile
```

- `profile.csv`: Stores batch processing time, images per second,
  peak GPU memory, parameter count, and forward FLOPs per image
  for both patch sizes.

The profiling results include inference and training-step measurements,
hardware information, and batch size.

### `results/sanity/`

Generated by:

```bash
python main.py smoke
python main.py sanity
python main.py trace --experiment baseline_p4
```

- `smoke_seed0.json`: Results from a small CPU training run using fake data.
- `overfit_curve.json`: Loss values from 300 training steps on 32 fixed images.
- `shape_trace.csv`: Tensor shapes after each model component.

Figures generated from the experiment results are saved in `docs/figures/`.


## Troubleshooting

- If Colab disconnects during the ablation, run the command again.
  Completed runs are skipped.

- If you change the experiment settings, move or remove the old
  ablation result files before running the experiments again.

- Peak GPU memory in `profile.csv` (column `peak_mem_mb`)
  is measured in MiB (2^20 bytes).

- Profiling uses float32, while full GPU training uses
  automatic mixed precision (AMP).

- If Colab does not detect a GPU, run `nvidia-smi` to check
  GPU availability and make sure the runtime is set to GPU.
